# 空数据与异常兜底策略

## 原则

所有业务数据都允许为空。前端、后端、地图、AI 查询、GeoServer、Cesium 接入都不得因为空数据或外部服务不可用而白屏。

合法空 GeoJSON：

```json
{
  "type": "FeatureCollection",
  "features": []
}
```

## 前端空状态

自习室无数据时显示：

```text
暂无自习室数据，等待数据组补充。
```

POI 无数据时显示：

```text
暂无校园 POI 数据，等待数据组补充。
```

AI 推荐无数据时显示：

```text
暂无自习室数据，无法进行推荐。
```

GeoServer 不可用时显示：

```text
GeoServer 图层暂不可用，当前使用本地数据或空数据展示。
```

Cesium 无数据时显示：

```text
暂无可用于三维展示的数据。
```

## 字段缺失

字段缺失时不要报错。展示层统一使用：

```text
未知
```

例如：

- 名称缺失：显示“未知地点”。
- 开放时间缺失：显示“未知”。
- 座位数量缺失：显示“未知”。

## 后端兜底

后端读取数据文件时：

- 文件存在且合法：返回原始 FeatureCollection。
- 文件不存在：返回空 FeatureCollection。
- 文件非法：返回空 FeatureCollection，并在响应中附带错误说明或日志。
- 不因为缺失数据返回 500。

## AI 查询兜底

AI 推荐需要处理：

- 自习室数据为空。
- AI API Key 未配置。
- AI API 超时。
- AI 返回内容无法解析。
- AI 推荐的自习室无法匹配现有点位。

推荐策略：

- 无数据：返回“暂无自习室数据，无法推荐”。
- 无 API Key：返回清晰提示，或使用本地规则兜底。
- AI 超时：提示稍后重试。
- 无法匹配点位：展示文字推荐，不强制地图定位。
